Why are ROC curves not suitable for imbalanced datasets? 🤔

I wrote a thread on ROC curves vs. Precision-Recall curves yesterday, but I didn't articulate this point well enough.

Let's take an example - look at the confusion matrix below and let's dive in... 👇  \n\n---\n\n First, if you want to have the background of the discussion or learn how to read ROC curves and Precision-Recall curves, checkout out my previous thread:



Now back to the example 👇 \n\n---\n\n We are obviously dealing with a severely imbalanced dataset - 1000 samples for class 0 and only 10 for class 1. This is not uncommon in practice, though.

The classifier is also not particularly good, because it has a lot of false positives.

Let's compute some metrics 👇 \n\n---\n\n ROC

To draw a ROC curve we need to compute the True Positive Rate (TPR) and the False Positive Rate (FPR). In this case:

TPR = 90%
FPR = 5%

Remember, a good classifier has high TPR and low FPR (upper left corner on the ROC curve). This looks quite OK.

Or is it? 👇  \n\n---\n\n Precision-Recall

Let's compute the metrics for the Precision-Recall curve.

Precision = 15%
Recall = 90% (same as TPR)

Now, this is a different story. We want both precision and recall to be high (upper right corner of the curve), so this classifier clearly isn't good!

👇  \n\n---\n\n A better way to understand this is to visually look at what is computed. Look at the image.

You see how in the case of Precision-Recall, we don't look at the True Negatives at all. So it doesn't matter if they are as much as the positive classes or much more!  \n\n---\n\n And by the way, this is also the reason that we can use Precision-Recall for Object Detection with a practically infinite background class, but we can't use ROC 😉 \n\n---\n\n This is a great point! I was implicitly assuming a constant distribution during training and test time, but if it changes it is trickier.
